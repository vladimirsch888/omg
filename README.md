# Service Banner — виджет для amoCRM

Показывает текстовое уведомление над списком сделок (режим карточек/канбан),
под строкой поиска и фильтра. Текст задаёт администратор, видят его все
пользователи аккаунта. Пример: «Аккаунт находится на обслуживании».

Состоит из двух частей:

- `widget/` — сам виджет amoCRM (manifest.json + script.js).
- `server/` — Node.js/Express-бэкенд, который хранит текст баннера и отдаёт
  его всем пользователям аккаунта. OAuth к amoCRM API не используется —
  бэкенд не обращается к amoCRM вообще, это простое key-value хранилище
  «домен → текст», защищённое общим токеном.

## Как это работает

1. Виджет устанавливается в аккаунт amoCRM как приватная интеграция. При
   установке администратор указывает в настройках виджета (стандартный
   диалог настроек amoCRM) два поля: `api_url` — адрес вашего бэкенда и
   `api_token` — секретный токен администратора.
2. Открыть настройки виджета (Настройки → Интеграции) в amoCRM может только
   пользователь с соответствующими правами — этим ограничением amoCRM сам
   решает задачу «редактировать может только администратор», без
   дополнительного кода с нашей стороны.
3. Текст самого баннера редактируется через простую HTML-админку бэкенда
   (`/admin.html`) — там администратор вводит домен аккаунта, токен и текст.
   Так удобнее, чем каждый раз лезть в настройки виджета в amoCRM.
4. На странице списка сделок (`llist`) script.js виджета раз в 60 секунд
   запрашивает `GET /api/banner?domain=...` (без авторизации — чтение
   публичное, чтобы не пришлось передавать секретный токен в браузер
   каждого рядового пользователя) и вставляет/обновляет баннер в DOM.

## widget/ — установка в amoCRM

1. В `widget/manifest.json` замените `secret_key` на значение, которое
   amoCRM выдаст при создании приватной интеграции (Настройки → Интеграции →
   Создать интеграцию).
2. Замените `widget/images/logo.png` (и `logo_small.png`) на свою иконку —
   сейчас там залита однотонная заглушка 100×100/28×28, чтобы пакет был
   технически валиден.
3. Соберите содержимое папки `widget/` в zip (файлы должны лежать в корне
   архива, без вложенной папки `widget/`):
   ```bash
   cd widget && zip -r ../service-banner-widget.zip . -x '.*'
   ```
4. Загрузите архив в настройках вашей приватной интеграции в amoCRM.
5. В настройках виджета укажите `api_url` (адрес развёрнутого `server/`) и
   `api_token` (значение `ADMIN_TOKEN` из `.env` бэкенда).

### ⚠️ DOM-селекторы — обязательно проверить

Разметка страницы списка сделок отличается между версиями интерфейса
amoCRM/Kommo, и у меня не было доступа к живому аккаунту, чтобы сверить
точные CSS-классы. В `widget/script.js` список кандидатов-селекторов вынесен
в константу `CONTAINER_SELECTORS` в начале файла:

```js
var CONTAINER_SELECTORS = [
  '.pipeline_leads__filter',
  '.control-bar',
  '.linked-filter-container',
  '#pipeline_leads',
  '.js-pipeline-content',
  '#content'
];
```

После установки откройте список сделок, через devtools найдите контейнер
строки поиска/фильтра, скопируйте его точный селектор и добавьте первым
элементом в этот массив (или замените неподходящие). Без этой проверки
баннер, скорее всего, всё равно появится (последний селектор — `#content`,
общий контейнер страницы), но не обязательно ровно под строкой фильтра.

## server/ — развёртывание бэкенда

```bash
cd server
cp .env.example .env   # задайте ADMIN_TOKEN
npm install
npm start               # либо npm run dev для авто-рестарта
```

Эндпоинты:

- `GET /api/banner?domain=<поддомен>` — публичное чтение текста.
- `PUT /api/banner` с `Authorization: Bearer <ADMIN_TOKEN>` и телом
  `{"domain": "...", "text": "..."}` — запись/обновление текста.
- `GET /admin.html` — простая HTML-панель для администратора (ввод домена,
  токена и текста баннера).
- `GET /health` — проверка живости.

Хранилище — файл `server/data/banners.json` (создаётся автоматически).
Для продакшена рекомендуется:

- задеплоить за HTTPS (Render, Railway, VPS + nginx и т.д.);
- при желании сузить `ALLOWED_ORIGINS` в `.env` до доменов вашего аккаунта
  amoCRM/Kommo вместо `*`.

## Ограничения и оговорки

- Проверка «админ/не админ» для доступа к настройкам виджета выполняется
  amoCRM на уровне интерфейса, а не в коде этого виджета — если у вас
  нестандартные роли, убедитесь, что доступ к Настройкам → Интеграциям
  ограничен нужным кругом пользователей.
- `ADMIN_TOKEN` — единственный секрет для записи; это простая защита, а не
  полноценная модель прав. Для более чувствительных сценариев стоит
  добавить отдельные токены на аккаунт или интеграцию с amoCRM OAuth.
- Список `CONTAINER_SELECTORS` нужно свериться с реальной версткой вашего
  интерфейса (см. раздел выше) — я не смог проверить это на живом аккаунте.
