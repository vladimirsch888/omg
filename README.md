# Service Banner — виджет для amoCRM

Показывает текстовое уведомление над списком сделок (режим карточек/канбан),
под строкой поиска и фильтра. Текст задаёт администратор, видят его все
пользователи аккаунта. Пример: «Аккаунт находится на обслуживании».

Виджет полностью бессерверный: никакого бэкенда, хостинга или OAuth не
требуется. Текст хранится прямо в настройках виджета amoCRM — это встроенное
хранилище amoCRM, единое на весь аккаунт.

## Как это работает

1. Виджет устанавливается в аккаунт amoCRM как приватная интеграция.
2. Текст баннера — это поле `banner_text`, объявленное в
   `widget/manifest.json`. amoCRM сама рисует для него стандартную форму в
   диалоге настроек виджета (Настройки → Интеграции → виджет → шестерёнка
   настроек) — отдельный UI писать не нужно.
3. Открыть эти настройки может только пользователь с соответствующими
   правами в amoCRM (обычно — администратор аккаунта). Так amoCRM сама
   решает задачу «редактировать может только администратор».
4. На странице списка сделок (`llist`) script.js виджета читает текст через
   `self.get_settings().banner_text` и вставляет/обновляет баннер в DOM.

### О «мгновенности» обновления

Текст обновляется у пользователя при следующей загрузке страницы (или при
переходе в другой раздел amoCRM и обратно в список сделок), а не «живьём» в
уже открытой вкладке. Для уведомления вида «идут технические работы» это
обычно не критично.

## Установка

1. В amoCRM: **Настройки → Интеграции → Создать интеграцию**. amoCRM выдаст
   `secret_key` — вставьте его в `widget/manifest.json` вместо
   `CHANGE_ME_GENERATED_BY_AMOCRM_ON_INTEGRATION_CREATION`.
2. Замените `widget/images/logo.png` и `logo_small.png` на свою иконку —
   сейчас там залита однотонная заглушка 100×100 / 28×28, чтобы пакет был
   технически валиден.
3. Соберите содержимое папки `widget/` в zip (файлы должны лежать в корне
   архива, без вложенной папки `widget/`):
   ```bash
   cd widget && zip -r ../service-banner-widget.zip . -x '.*'
   ```
4. Загрузите архив в настройках вашей интеграции в amoCRM и сохраните.
5. Откройте настройки виджета, впишите текст в поле «Текст уведомления»
   (`banner_text`) и сохраните.
6. Откройте список сделок в режиме карточек — баннер должен появиться под
   строкой поиска/фильтра.

## ⚠️ DOM-селекторы — обязательно проверить

Разметка страницы списка сделок отличается между версиями интерфейса
amoCRM/Kommo, и у меня не было доступа к живому аккаунту, чтобы сверить
точные CSS-классы. В `widget/script.js` список кандидатов-селекторов вынесен
в константу `CONTAINER_SELECTORS` в начале файла:

```js
var CONTAINER_SELECTORS = [
  '.pipeline_leads__filter',
  '.control-bar',
  '.linked-filter-container',
  '#pipeline_leads',
  '.js-pipeline-content',
  '#content'
];
```

После установки откройте список сделок, через devtools найдите контейнер
строки поиска/фильтра, скопируйте его точный селектор и добавьте первым
элементом в этот массив (или замените неподходящие). Без этой проверки
баннер, скорее всего, всё равно появится (последний селектор — `#content`,
общий контейнер страницы), но не обязательно ровно под строкой фильтра.

## Ограничения и оговорки

- Проверка «админ/не админ» выполняется amoCRM на уровне интерфейса, а не в
  коде этого виджета — если у вас нестандартные роли, убедитесь, что доступ
  к Настройкам → Интеграциям ограничен нужным кругом пользователей.
- Поле `banner_text` в манифесте имеет тип `text` (однострочное поле в
  стандартной форме настроек amoCRM) — сам текст при этом не ограничен по
  переносам строк, только визуально в поле ввода это менее удобно для
  длинных сообщений.
- Обновление текста не мгновенное для уже открытых вкладок — см. раздел
  выше.
- Список `CONTAINER_SELECTORS` нужно сверить с реальной вёрсткой вашего
  интерфейса (см. раздел выше) — я не смог проверить это на живом аккаунте.
